# Step 3 bounded provider capture amendment (frozen)

The frozen workspace allowance is one cumulative 32 MiB metadata and 4096-operation budget per bounded invocation. Existing scope-only ProjectionWatermarkProvider::capture and EventArchiveProvider::capture cannot establish that allowance for provider-owned I/O. This amendment makes that existing requirement explicit without changing V7 APIs or snapshot/reference wire bytes.

Add a public opaque nonserializable WorkspaceCaptureIo context, constructed only by the workspace service and borrowing the invocation budget and its already-validated ScopedStorage. It exposes only bounded read operations: stable selector reads at 64 KiB+1 with at most four attempts, and immutable RequiredObject reads using the declared exact length+1 and SHA-256 with a 4 MiB object ceiling. Context methods reuse WorkspaceIoBudget, charge returned HEAD ownership, failures and retries, and expose neither the backend handle nor mutation operations. Domain source preparation borrows the same budget through RetainedSourceCaptureContext.

Add defaulted bounded capture methods to both provider traits. Their default is UnsupportedOperation; it must never forward to the legacy capture method. V8 and mixed invocations select the bounded path from trusted registry configuration before the first snapshot read and invoke only the bounded methods. V7-only invocations retain existing methods and construction behavior. Existing providers therefore remain source compatible; bounded synthetic provider implementations explicitly implement the new method and perform every storage call through the supplied context. Empty synthetic providers return their existing zero-I/O cuts. Provider metadata and required-object lists remain independently validated by the workspace service.

A bounded method does not authorize a foreign backend or confer retained source authority. The service, store and adapter must still share the configured live backend identity and exact durable binding. No snapshot/provider field supplies those capabilities. Qualification applies only to tested bounded provider implementations, whose actual backend counters and outer allocation measurement must agree with the shared invoice; an arbitrary custom implementation that bypasses the context is nonconforming.

Retained directory reads, updates, independent transition verification, immutable writes and collision readbacks share the same invocation budget. Ordinary directory formats and V7 methods do not change. Charge page probes and storage calls before I/O, and returned PUT metadata immediately after return before further I/O. The context does not claim backend preallocation bounds for HEAD/PUT metadata.

Required regression evidence: legacy-only providers cannot be silently invoked by a bounded snapshot request; two providers consume one shared allowance rather than resetting it; oversized provider selectors and declared immutable lengths reject boundedly; provider-required object digest/length mismatches fail closed; default V7 workspace tests remain passing. Complete actual capture, epoch/pointer fault schedules and final resource accounting remain mandatory before claiming Step 3 completion.

Clarifications: mixed invocations call bounded methods for every provider, including V7 domains, and reject a legacy-only provider without invoking its legacy method. The context is passed by mutable borrow; provider reads and service verification rereads are separate charges on the same invoice. The 4 MiB provider RequiredObject ceiling is a new V8/mixed admission rule, not an existing RequiredObject invariant; apply it to provider reads, service object verification, and restore preflight object scans. V7-only remains unchanged. Post-PUT metadata rejection performs no further I/O; a possibly sent pointer then requires recovery rather than resend.
