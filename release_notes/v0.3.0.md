# Release Notes for v0.3.0

## Highlights

- Standalone authenticated catalog API with local or remote Tier1 compaction.
- Operator-owned HTTP worker dispatch and sweeper repair using the canonical worker envelope, stable task identity, explicit capacity refusal and uncertain-response recovery. HTTP timers and priority are unsupported.
- Immutable accepted Flow plans preserve deployment, execution and input declarations across later deployments, restart, partial event publication and concurrent replay. Incomplete legacy reservations without proof fail closed.
- Versioned publication metadata separates worker computation success from owner-verified readable output; publication can be retried independently of computation.
- Typed catalog read handoff binds authenticated workspace scope, one authority/projection cut and four exact Parquet files. The control-store route remains operator-only and default-off.
- The R2 qualification architecture adds a protected native API/Flow lane with independent owner-side scope attestation, typed denied-bucket verification before writes, accepted-CAS recovery, fresh-cache and retained-reader checks. Its live campaign remains a release gate until a final-candidate receipt is reviewed.
- Existing Rust, Python and CLI packages declare 0.3.0. Consumers own SQL validation, engines, hosting and delivery policy; Turntable is not a dependency.
