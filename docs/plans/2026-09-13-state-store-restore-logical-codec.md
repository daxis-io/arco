# Step 3 logical restore codec revision 2

Preserve the ordinary logical-v2 codec unchanged. Reuse its existing canonical byte primitives and logical commit-ID derivation; use a separate restore-history tag so restore cannot be confused with a bounded ordinary write set. This freezes logical bytes before restore implementation or measurements.

Present mode: result sequence is exactly current sequence+1, prior history is current history. Absent mode: result sequence is exactly source sequence+1, prior history is source history. Checked overflow rejects. Present mode does not introduce a maximum(source,current) sequence rule; it preserves restore-plan6 behavior.

Canonical primitives match logical_v2.rs: byte strings are u64 big-endian length followed by exact bytes; digests are32 raw SHA-256 bytes; sequence/count are u64 big-endian; version is u32 big-endian; scope is tenant/workspace/domain byte strings in that order. Timestamp uses signed64-bit big-endian UTC seconds followed by u32 big-endian nanoseconds. No arbitrary value is parsed or normalized.

Request digest preimage: byte string tag `arco/control-v2/restore-request`, u32 envelope version2, scope, u32 restoreRequestVersion1, mode byte(0 present,1 absent), source logical sequence, source logical-history digest, byte string restore ID, original immutable request timestamp. Physical snapshot IDs/manifests/roots, object versions, fences, participant attempt numbers, workers and retry counts are excluded. The operation ID is the restore ID, family is `workspace-restore-v2`. Existing logical_v2::commit_id hashes this operation/request digest with prior history and result sequence. Replacement attempts recompute state-dependent identity from the new authenticated logical base but do not change stable operation/request inputs. A different physical partitioning of equivalent logical fixtures must not change the identity.

One V2 notice has intent ID `restore-<restore_id>`, projection kind `workspace-restore-v2`, exact target/output scope (source scope must equal target scope), result sequence, logical commit ID, ordinal0. Its deterministic JSON payload is encoded by a fixed-field struct, in this order: restoreId(string), mode(string present/absent), sourceLogicalSequence(u64), sourceLogicalHistory(lowercase raw hex digest), resultLogicalSequence(u64), requestedAt(UTC RFC3339 with exactly9 fractional digits and Z). It contains no physical provenance or participant attempt. Existing ProjectionIntentV2 validation and encoding apply. The notice ID must be absent in the inherited paired outbox indexes; an existing unrelated incarnation is a conflict, never silently trimmed/restaged. An exact already-committed restore is reconciled through its existing plan/journal.

Restore history preimage: byte string tag `arco/control-v2/restore-history`, u32 envelope version2, scope, u32 restoreHistoryVersion1, prior logical-history digest, result sequence, logical commit-ID digest, u64 declared canonical mutation count, then exact write tuples in strictly increasing key order using the existing logical_v2 write-tuple bytes(generation, tombstone/value semantics unchanged), then existing logical-v2 additions encoding for the single notice and trims encoding for an empty list. Only rows whose value/generation change relative to the logical base contribute mutations; absent mode uses the source as its logical base. Equal visible current values and preserved tombstones do not become mutations. The final verifier streams tuples without collecting a vector, checks actual count against the declared count, and rejects order/duplicate/generation errors. Counts from untrusted unit receipts do not become authoritative until complete streamed verification succeeds.

Source and current physical provenance are separate restore-certificate fields. Source logical history is bound through the request digest; physical source descriptors bind candidate KV root after that root is built and are excluded from logical notice/history bytes. No manifest self-hash cycle is introduced.

An independent Python oracle will reconstruct exact preimages, IDs, mutations and history from published tuples. Required cases include arbitrary binary values/keys, equal-value different generations, delete/recreate, present source-only tombstones, absent inherited source tombstones, both modes, identical frozen logical input on different physical layouts, and tampered physical provenance rejection.

## Normative validation and review dispositions

Only same-scope restore is supported. Source, target/base, notice and history StateScope must be equal before planning. Source sequence/history are derived from the authenticated source manifest witness; repeated plan/notice fields must match. The plan freezes exact target base logical sequence/history, authenticated physical roots and source witness. Final seal rejects any changed base; it never rebases prepared output. Existing logical commit-ID encoding already binds base history and result sequence, so the stable request digest does not duplicate base fields.

The participant attempt is frozen and authenticated in the physical plan, progress, journal and candidate provenance; it is excluded from logical request/history identity with worker/retry counts. This clarifies revision3's freeze sentence: freezing execution identity does not mean hashing it into logical identity. A new selected attempt over an equivalent logical base with the same original request has the same logical identity; its physical plan is distinct and old-attempt progress cannot be adopted.

The separate restore request/history version1 follows Canonical::new's existing tag, envelope-version2 and scope prefix. The ordinary codec and envelope version2 are unchanged. A declared mutation count may initialize the streaming hash before it is trusted. The final verifier accepts the digest only after independently proving complete merge coverage and actual count equality; it publishes nothing before this check. This matches existing SyntheticGenesisHistory validation and requires no extra total-input counting pass. Reject overflow, excess, shortage, duplicate or out-of-order tuples; finish consumes the untrusted builder and returns a result only after all checks.

Mutation table (all sequences checked for overflow): present equal visible values preserve current generation and emit no mutation; source-visible changed/new/revived keys emit Some(value) at result sequence; current-visible keys with no visible source emit None at result sequence; current tombstones with no visible source remain unchanged; source-only tombstones are not imported. Absent mode emits each source-visible value at result sequence, and inherits source tombstones/generations unchanged with no mutation. A source tombstone is absence for visible replacement. Never copy a source generation into present-mode output. Each emitted write tuple is length-framed exact key, u64 result generation, then byte0 for deletion or byte1 and length-framed exact value. Arbitrary binary keys and values remain opaque.

Restore ID uses the existing immutable workspace ID validator, then logical_v2::validate_id for the operation and generated `restore-<id>` notice; enforce the existing maximum enclosing metadata/payload and ID limits before allocation. Do not invent a second normalization. Payload uses serde_json::to_vec of a deny_unknown_fields fixed-field struct with precisely the previously listed fields/order and no defaults or optional fields. Decode/reencode must equal exact bytes. requestedAt is derived only from the immutable request instant, formatted by UTC RFC3339 with exactly nine fractional digits and Z; reject leap-second/nanosecond values >=1_000_000_000 and noncanonical payload timestamps. The request preimage encodes signed UTC seconds as their exact 8-byte two's-complement big-endian representation plus u32 nanoseconds; it does not hash localized strings.

After the mutation tuples, append u64 count1, then the existing intent tuple: u32 envelope version2; framed intent ID; framed projection kind; scope; u64 result sequence; raw logical commit digest; u64 ordinal0; framed payload bytes. Append u64 trim count0, even when empty. No physical descriptor or attempt enters these bytes.

Before collision handling, exact replay requires authenticated selected plan/journal/candidate reconciliation. Matching notice bytes alone never attest commitment; verify original request identity, result sequence, commit ID and physical plan/attempt witness. Any unrelated active notice incarnation is conflict and cannot be trimmed/restaged. Notice fields must match authenticated source and target/result witnesses. Tests include both modes, all mutation table branches, binary bytes, count failures, attempt/progress substitutions, changed frozen base, noncanonical payloads, same logical fixtures on different partitions and independent provenance tampering.
