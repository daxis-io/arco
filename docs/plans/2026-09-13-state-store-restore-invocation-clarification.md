# Restore invocation and progress clarification

Frozen for API, authority, recovery ordering and runtime accounting semantics after independent review. Exact Plan7/receipt/progress/selector/seal wire encodings remain a separate required freeze before their implementation. No runtime or budget result is claimed. Preserve V7-only behavior and V6 plan bytes.

## One coordinated unit

Add `RestoreParticipantAdvance::{Terminal(RestoreParticipantInspection), InProgress { completed_units: u64 }}`. The default `StateRestoreParticipant::advance_restore(plan, context)` forwards to existing `apply_restore(plan, context.observed_now())` and wraps Terminal on the legacy V7-only route. A bounded context must reject the default before invoking legacy I/O; a bounded participant must explicitly implement that route. V8 overrides advance and its old apply entry rejects unsupported. No new public inspection variant.

The context must be an opaque, nonserializable `RestoreAdvanceContext<'a>` constructed only by WorkspaceRestoreService after authenticating the selected Applying/RepairRequired attempt, active original source pin, source cut and participant plan. A `(plan, now)`-only advance signature cannot carry the required held lock, epoch, shared budget or selected owner into the final publication capability; do not substitute task-local ambient state or an adapter-global active job.

The private bounded context borrows the existing held workspace apply `LockGuard`, owned `RetentionMutationEpoch`, and the ONE outer `WorkspaceIoBudget`. It carries the selected participant identity/plan raw digest, selected journal path/version and exact attempt identity, immutable requested_at and checked execution_deadline, source deadline, trusted scope/storage binding, and fresh observed time. Its private refence method renews the held lease before expiry, checks original deadlines, and authenticates the journal still selects the same participant plan/owner. Refence I/O remains control admission. No caller can mint the context from a persisted seal, candidate identifier or plan bytes alone.

Context representation can use a private Legacy/Bounded payload so public V7 defaults stay source compatible. Do not advertise mixed bounded V7 apply support merely because its default forwards: it needs an explicit bounded implementation or must fail closed. This explicitly clarifies the frozen default-forwarding clause: default forwarding is legacy-mode-only; bounded mode fails closed before adapter I/O unless explicitly implemented.

The first implementation should reuse the existing journal and apply coordination; no second workspace journal or general storage wrapper. V7-only flow retains legacy I/O and default forwarding. V8/mixed entry acquires the one control invoice BEFORE the first request/snapshot/journal read and passes it through every helper, adoption/retry and participant.

On InProgress, keep Applying with no evidence or readable manifest; settle/release the per-invocation coordination and return immediately without visiting a second participant. No completed_units field is added to the workspace journal: progress counts live in authenticated participant progress. On an error, distinguish exact authenticated nonterminal progress from ambiguous publication; once a prepared candidate may exist the adapter cannot return Ready or InProgress and restart performs read-only reconciliation.

After bounded authentication of the selected journal and immutable plan, and before generic Ready-based replacement/adoption, selected Plan7 participants in Applying/RepairRequired receive a PRIVATE service resume classification. Run a separate bounded read-only inspection before source/pin/deadline gates; this inspection context has the shared control budget and selected identity but no lock, epoch, source authorization or publication capability. Visible/Superseded may reconcile selected metadata after source expiry or pin release. Ready preserves the selected plan and only then enters active-source/pin/deadline validation and coordinated advance. Generic legacy inspection is skipped for Plan7; bounded inspection is required. Preserve their exact selected plan regardless of whether the first unit has selected progress. The V8 advance authenticates that progress; a corrupt or expired job remains RepairRequired rather than becoming a new Prepared attempt. Existing superseded target handling is terminal and cannot rebase completed output. Ordinary V6 replacement paths keep their existing semantics.

A separate opaque nonserialized planning context carries observed_now, immutable requested_at and checked requested_at+24h, plus the borrowed control budget in bounded mode. Default planning forwarding calls legacy plan_restore with observed_now only in legacy mode; bounded mode cannot silently invoke legacy reads. Bounded inspection also needs an explicit shared-budget context route: legacy inspect_restore has no budget argument. Preserve read-only exact-candidate inspection after source/execution expiry; those deadlines gate new work and publication, not proof that a candidate already committed. V8 plans persist and validate exact derivation. Reject future requested_at before first immutable request publication; retries and replacements cannot reset the deadline.

## Plan and unit records

Use a separate `PersistedRestoreParticipantPlan::ControlMvpV7` payload, leaving the existing `ControlMvp` V6 variant encoding untouched. Add common source()/identity() accessors to avoid irrefutable legacy matches; format validation remains in the participant. New plan payload is canonical deny-unknown-fields metadata capped at 4 MiB. Preserve exact raw plan bytes and the existing outer plan digest when decoding the workspace attempt.

The V7 payload binds authority8, scope and trusted durable binding; existing RestoreAttemptIdentity; exact original source reference and raw manifest/root witnesses; present or absent target witness; exact present HEAD raw bytes/version and writer/reclamation fences; current/source logical history/sequence; original requested_at, execution deadline and source deadline; result sequence/logical ID; deterministic physical candidate identity; and stable selected plan owner generation. Physical IDs, attempts and fences do not enter the frozen logical restore codec.

A unit receipt, current progress and selector are each capped at 4 MiB. The receipt binds exact plan raw digest, participant attempt/owner generation, ordinal, predecessor receipt raw digest, Start/After(exact key)/End source/current/global cursors and singleton phase, exact selected input witnesses, ordered output descriptor witnesses and deterministic semantic counts. Per-ordinal paths are deterministic under the selected participant attempt. Never retain/reverse a full receipt collection. The progress selector uses exact version CAS; one advance reads only selector/current/direct predecessor/new receipt.

Owner generation here must identify the durable selected plan, not the short-lived lock holder or changing retention epoch. Otherwise a new worker would change immutable ordinal receipt bytes solely because it acquired the next invocation's lock, making exact retry conflict with a valid prior worker. Lease/epoch ownership belongs in the live context/refence proof and publication provenance; stable plan ownership remains in each receipt. A replacement participant attempt receives different physical paths and cannot adopt prior progress.

Output segment IDs derive deterministically from candidate identity, unit ordinal and bounded output-part index using existing immutable ID encoding. A retry uses the same bytes/IDs or returns a typed immutable conflict. It never generates fresh random segment IDs after a known conflict. Output Arrow/index/descriptor codecs and role roots remain production v1 physical descriptors.

Deterministic count clarification: receipt counts must be deterministic semantic work (selected descriptors/encoded input/output/decoded rows/mutation counts and declared work reservations). Exact actual I/O/metadata capacities/failures/retries are invocation measurements: they cannot all be encoded in an immutable receipt before that receipt's own write/response and progress CAS have occurred. They must be fully retained in the execution evidence and monotonic runtime ledger, without pretending semantic counts are actual I/O. The final verifier independently recomputes receipt semantic counts; missing actual runtime counters remain nonpassing. Do not encode cache-dependent actual counts as deterministic ordinal receipt identity.

## Required component tests before behavior changes

- A default legacy participant forwards exactly one apply call and preserves terminal results.
- A participant returning InProgress leaves Applying/evidence None, settles/releases, and prevents a second participant advance in that public invocation.
- A selected Plan7 with partial progress receives bounded inspection and resumes under the same plan digest from Applying and RepairRequired, never replanned as Prepared; generic legacy inspection and replacement planning are forbidden. Already-committed Visible is recovered after source expiry/pin release without constructing a mutation capability.
- A persisted seal or arbitrary plan cannot construct a live publication context; mismatched scope/binding/owner, journal replacement, deadline equality or lease loss prevents prepared/HEAD publication.
- Original request future time, checked-add overflow, exact 24h boundary and retry/replacement deadline preservation.
- Same selected unit reexecution produces identical receipt/output identities despite cache state, retry count or a new lock holder; actual counters still include all attempts.

These tests establish component behavior only. Real bounded merge/final verification, large fixtures, full workflow fault coverage and independent final-source audit remain required.

## Control-read implementation constraint

Current WorkspaceIoBudget::read_stable reserves the fixed cap+1 for each probe, intentionally correct for catalog/retained 64 KiB pointers. Repeated 4 MiB journal/plan/progress probes would consume the 32 MiB cumulative invoice even when the actual records are small. Restore metadata may instead use a narrowly named exact-sized stable-record helper: HEAD-before validates nonempty version and 1..=4 MiB size; reserve observed size+1; bounded range GET; HEAD-after requires identical nonempty version and exact observed/returned size; changed versions retry at most four times and each attempt is charged. Preserve fixed pointer probes unchanged. Initial present-then-missing metadata is an error, never an absent journal/genesis. No raw GET, caller-supplied size authority, counter reset, or allocation before admission.

Centralize this at the existing restore record read helpers (load_journal/load_optional_journal/get_optional_raw/load_selected_attempt) and route their callers through the same borrowed invocation context. Initial source record/request/attempt/journal, terminal-winner adoption, recover_restore's first request read and get_restore's first journal read must all enter that context before storage. Immutable writes keep exact collision readback and post-response capacity accounting; journal CAS reconciliation reuses the same context. This is a metadata probe choice inside the frozen 4 MiB encoded cap and 32 MiB cumulative control invoice, not a larger request budget.
