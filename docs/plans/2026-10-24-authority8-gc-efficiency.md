## Actual cost model

Let E be traversed protected edges (including overlap), U unique immutable metadata objects, R selected roots, P candidate inventory pages, B bounded traversal units, C objects per inventory page (<=256), F refence cost (bounded root/selector inventories). The baseline constructs 889 transcript pages for 28,372 leaf descriptors: 582,675 calls, then 410,771 verification/filter calls per candidate page. Setup/admission adds 210: 993,656 total. Producer: 171,172 external-key GETs for 19,412 stored key objects; 56,744 descriptor GETs, 56,744 index GETs, 56,744 data HEADs, 113,488 index HEADs. Proof writes total 440,423,529 bytes. Verification repeats physical authentication and full snapshot capture. Baseline total is O(E + B*F + P*(E + B*F)); complete-sweep projection must be labeled, not measured.

Backend counters wrap each MemoryBackend operation; these are logical backend calls, not S3 traffic. Source inspection found a hidden HEAD in ObjectStoreBackend::get_range before its range GET. For successful nonempty GC reads, the source-derived no-retry upper model is logical calls plus range GET calls plus conditional precondition failures (whose adapter fallback reads HEAD). Failed ranges can overcount because their initial HEAD may deny the GET. SDK retries remain below that boundary and must be counted by a provider transport hook. The ordered object_store list stream may fetch up to 1,000 metadata rows while Arco consumes 256, so logical returned metadata is not wire traffic; retain this bound separately. This investigation does not change the shared provider adapter. Directory replay CPU charges are not provider requests. Range GET is one request per object/range, never an implicit batch. Fixture construction is separate.

## Selected invariants and recovery

The existing producer stores version-2 root scheduling pages (no copied edge metadata). The independent verifier derives every root from the fully validated seed and traverses directory pages using existing decoders and fence validation. It authenticates physical descriptor, owner/index identity, block coverage, and exact segment/index versions. Only verified reachability inserts paths into a fixed 1 MiB Bloom filter; seven SHA-256-derived positions are ORed, never cleared. All insertions precede session completion, so a negative lookup implies no visited protected path equals the candidate. Hash collisions can retain extra orphans only. The filter is opaque, never deserialized or trusted from storage; a completion flag/count/checksum cannot replace traversal. A crash discards it and restores trust by one complete bounded walk, regardless of inventory page count. No protection is released on expiry.

Bound the DFS frontier by directory fanout/depth; charge resident and staged copies, key cache, filter, hashing/decoding, and requests to the existing invoice. Commit staged state only after a successful refence. Cancellation and failed I/O leave the caller's state unchanged. Authenticate the full seed at admission; compare HEAD, retained selector, pin and manifest version inventories, exact snapshot/export record versions returned by their owning stable reads, restore journals, and mutation epoch before/after advances and candidate return. Root publication, selector/pin changes, and relevant epoch changes invalidate the sweep. An inventory page is version/size revalidated at return. Original immutable source metadata remains protected even if later corrupted; changed candidate versions fail. Session state cannot authorize DELETE.

## Frozen acceptance thresholds

- Unchanged 2,419,200 retained / 1,048,576 disjoint target / 65,536 outbox fixture; one-page total <=99,365 backend calls (>=10x). Investigate 100x (<=9,936), but 28,372 separately stored descriptors already exceed that cold lower bound without a packed on-disk format. Record failure rather than relax thresholds.
- Optimized complete sweep actually executes: <=250,000 calls, no Arrow payload reads, HEAD CAS or DELETE; exact orphan/protected membership checked by an independent oracle. Baseline full sweep is a trace-derived projection if not run.
- One-page metadata read bytes <=150 MiB; persistent proof <=128 KiB, attempted proof writes <=256 KiB. Complete-sweep metadata reads <=200 MiB. Limits include proof construction/admission, exclude fixture construction.
- Every invocation <=4,096 charged operations and <=64 MiB admitted ownership; no unbounded cache. Subsequent inventory page <=512 calls on the frozen scope; no graph metadata reads. Restart <=one cold verification plus its admission, independent of P; failed unit replay <=4,096 calls.
- Correctness: no protected false negatives; small-state exact candidates; measure false-positive retention. Cover cold/restart/repeated restart, both prefixes, empty/protected/orphan-rich, independent E/P scaling, root/selector/version mutations, missing/corrupt/reordered proof, cancellation/lost responses/unavailable storage and budget exhaustion.
