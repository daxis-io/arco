# State-store capacity Step 4 implementation plan

> Executor: use `executing-plans`, `test-driven-development`, and `verification-before-completion` task by task. Commit, push, PR mutation, merge, cleanup, provider work, and production activation require separate authorization.

**Goal:** Add authenticated reachability, equivalent physical maintenance, protected retained roots, and bounded garbage collection for the private synthetic authority-8 state store.

**Architecture:** Extend the existing control-MVP retention lock, mutation epoch, 256-object GC page loop, and deletion path. Give authority 8 its own authenticated closure and maintenance certificate validation under the existing state-store owner; do not route it through authority-7 replay or make a second GC service. Stream each protected closure against the current candidate page with bounded working memory. Publish maintenance only after complete same-invocation equivalence verification. Authorize deletion only from a refenced protected-root inventory.

**Tech stack:** Rust 1.88; `arco-catalog`; existing `RootStorage`, `ControlMvpMaintenanceWorker`, `RetainedAuthorityRoots`, `RetentionMutationEpoch`, authority-8 directory and physical readers.

Reuse `RetainedAuthorityRoots` for workspace pins and the existing candidate-page/delete loop. This keeps one delete authorization and one reclamation fence.

Until the chosen traversal passes, authority-8 GC remains disabled. Age or path prefix alone never makes a candidate deletable.

## Late-DELETE-safe directory identity, required before active GC

The red fixture proves the current V8 directory wire cannot safely reclaim a reusable empty page after a delayed DELETE. Long-key objects have the same problem, and keeping every distinct long key forever fails bounded storage. The next implementation slice needs deterministic per-publication identity for **new** page and external-key objects while keeping old V1 bytes readable. A suitable minimal extension is a V2 page payload with a domain-separated publication salt and a V2 external-key payload identified by a spare high bit in `KeyRef.bytes`; both digests cover encoded bytes. The root and node layouts can remain unchanged. A candidate manifest or selected retained pointer must bind the exact salt/version used for its new pages; ordinary transaction, genesis, restore, retained selection, and maintenance writers must each use a stable unique candidate identity. Path-copy verification must compare old leaves by authenticated logical endpoints and digest rather than recomputing their old key references with the new salt. New readers accept old and new immutable pages; old readers fail closed on V2. Freeze vectors and run a compiled red interleaving for page and long-key reuse before enabling either class for deletion. This may require a new bounded cost qualification, so the current dry-run exclusion remains in force until then.

As of 2026-09-29, the directory layer has a test-only salted V2 page/key encoder and a V1/V2 reader. Compiled behavioral red tests showed reusable empty-page and external-key digests, a legacy long-key leaf rejected by salted path copy, and a V2 page header omitted from the probe ceiling; each is green in the directory slice. This does **not** migrate any authority-8 publisher: `with_publication_salt` is test-only, no candidate manifest or retained pointer binds a salt, and GC still excludes reusable objects. Before writer wiring, qualify the native restore writer's encoded-key allocation and object ceiling, bind unique identity to all publication paths, freeze exact vectors, and rerun the delayed-DELETE interleaving against a published successor.

Continuation, 2026-09-29: ordinary authority-8 transactions, synthetic genesis, retained-pointer updates, and final restore directory writes now derive V2 identities from their publication IDs. New manifest and retained-pointer records carry `directory_object_version: 2`; old records remain readable. Published post-fence empty-page and long-key delayed-DELETE tests pass. Present and absent Plan7 restore publication passes with V2 final roots, and native notice path copy verifies source long-key endpoints semantically before writing a different candidate identity. The V2 page/key framing has an independent fixed vector. The protected-root inventory and active deletion gates below remain open; this writer migration alone does not authorize GC.

Continuation, 2026-09-30: private authority-8 dry-run planning now validates the selected retained-source pointer and every directory member under a cumulative 4096-operation/64-MiB read ceiling. It authenticates each member descriptor and exact source-manifest digest. It also streams the existing validated workspace pin inventory, removing exact required paths and checking matching authority references. Compiled reds for a corrupt retained selector, missing selected descriptor, and corrupt workspace pin are green. This is partial root protection: retained expiry and the full active/in-flight root matrix remain unqualified, so authority-8 deletion remains disabled.

Further continuation, 2026-09-30: a compiled red showed that an armed restore epoch with no prepared descriptor still allowed an old orphan into a synthetic GC dry-run plan. The planner now reads the canonical bounded workspace epoch before and after its scan, rejects every in-flight epoch, and rejects a changed epoch version. This covers the unresolved armed boundary conservatively; active job artifacts outside a selected manifest and the full retention window still need independent protection. Active authority-8 deletion remains disabled.

Further continuation, 2026-09-30: compiled reds showed that an unpublished restore attempt and then an Applying journal before publication arming each admitted an old orphan. Releasing their exact artifacts requires an independent authenticated terminal proof and retention check; that release is not implemented. The scan caps inventory at 4096 objects and denies malformed or changed selected records. Active deletion remains disabled.

## Frozen invariants

- The protected set includes current HEAD, all attached and retained manifests, all three directory roots and their transitive pages/leaves/data, transaction/transition/genesis/restore provenance, outbox projection sources, retained-source selectors/descriptors, active snapshot and maintenance pins, and unresolved prepared/armed restore artifacts. A missing, corrupt, oversized, or budget-exhausted edge denies deletion.
- Authority-8 ordinary directory pages live under `control/directory/v1/domains/<domain>/`, outside the existing GC inventory prefix `control/v1/domains/<domain>/`. The retained-reference directory uses the latter prefix and a separate role. Inventory and closure must cover both exact prefixes with a tagged bounded cursor; an authority-domain-only sweep is incomplete.
- A retained authority-8 member remains readable until its exact reference deadline even after its workspace snapshot pin is released. A separate active pin still protects its source; releasing that pin only blocks new restore admission.
- Preserve the 30-day token window, 8-day preparation retention, and 7-day orphan eligibility. An elapsed deadline is necessary but insufficient for deletion. Never infer an unsent restore HEAD from missing prepared bytes, a seal, an expired request, or a journal state.
- A maintenance successor keeps logical sequence and history unchanged and proves complete ordered equality of key bytes, values, generations, tombstones, active outbox incarnations, and delivery order. Changed physical roots need a bound certificate; equal sequence/history alone is insufficient. Unselected subtrees are identical by reference. Readers authenticate maintenance ancestry before accepting retained tokens.
- The active delete pass holds the retention lock and exact mutation epoch, publishes a reclamation fence, then rechecks HEAD, protected roots, and candidate object version before each delete. Cancellation and uncertain publication leave objects protected or require read-only reconciliation; no guessed retry of authority CAS.
- Directory pages and long-key objects are content-addressed and reusable. A writer starting after the reclamation fence can attach an existing pre-fence page through `put_immutable_matching`; HEAD version fencing alone does not exclude that race. The synthetic V8 commit path now holds the retention GC lock across staging and extends its lease before HEAD CAS, with a red-before-green lock exclusion test. Audit genesis, restore, retained selection, and future maintenance publishers under the same rule before enabling deletion. Until then, authority-8 dry-run plans confer no delete capability.
- A compiled delayed-DELETE fixture then proved the remaining lease-expiry failure: after a GC fence, an outbox trim reused an unattached canonical empty directory page; deleting the old candidate path broke the new current read. Raw failure and source patch are retained as `authority8-delayed-delete-red.log` and `authority8-delayed-delete-red.patch` in the Step 4 evidence directory. The private dry-run now excludes the canonical empty page and all long-key objects. This is a conservative partial policy, not bounded directory GC: key objects need a versioned, nonreusable identity or an equivalent proof before their deletion can be enabled. Active authority-8 GC remains disabled.
- Each candidate page recomputes protection under the held lock and epoch. Audit every root/pin publisher for participation in that coordination before relying on it. If a later measured mark index is needed, incomplete or stale mark pages confer no deletion authority.
- One GC page and one maintenance unit have explicit object, byte, operation, and live ownership budgets. Exceeding them returns typed backpressure without deleting or publishing.
