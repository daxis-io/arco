## 1. Executive Verdict

The program has executed far more of the roadmap than the repository makes visible — and less than the merged PRs make it appear. Phases 1A through 7D are landed on `origin/main` via PRs #316–#322 with genuinely excellent test discipline. But three structural problems undercut the achievement:

**Problem 1 — The program's specification layer is not on the canonical branch.** The 1,163-line master roadmap and four of the six design docs exist only in one developer's local tree. The eight `docs/spec/*` contracts, both conformance fixtures, and the entire planner/runtime seam sit stranded in open PR #309, which went CONFLICTING when PRs #316–#322 landed overlapping files. Four plan documents merged to origin (`2026-07-01-prototype-promotion-fallback-gate-slice.md`, `2026-07-05-phase-4a-*`, `2026-07-06-phase-4b-*`, `2026-07-08-phase-6a-*`) cite the roadmap and spec files by paths that do not exist on that branch. Contributors implemented and merged Phases 4A–7D against contract documents they could not read.

**Problem 2 — Phase 3C was bypassed, and everything downstream is hermetic.** The promotion gate (`promotion_gate.rs`) is a correct advisory evaluator that no non-test code ever constructs; no benchmark for the control-store MVP exists anywhere; the gate encodes no numeric budgets; run today it would return `RejectAdvancement` with every measurement `Unavailable`. Its explicit reject criterion — "replay grows without bounded recovery" — is factually true today (issue #334: every read and commit replays the full transaction lineage from genesis). Yet Phases 4A, 4B, 5, 6, and 7A–D were all built on top of the unpromoted prototype, and every one of those surfaces is crate-private, `#[allow(dead_code)]`, with **zero production callers**, no IAM expression for the `state-store/` object prefix in `infra/terraform/iam_conditions.tf`, no alerts in `infra/monitoring/alerts.yaml`, and no runbooks for any of the roadmap's named failure states.

**Problem 3 — Gate evidence has integrity holes exactly where it matters most.** Real-provider (GCS/S3) CAS conformance and the sole-writer IAM invariant exist only as `#[ignore]`d, feature-gated tests behind CI steps that skip silently and pass green (issue #366). The revocation-freshness budget the roadmap requires before any grants migration was silently dropped by both Phase 6 child plans. Writer-epoch fencing — half of the strategy doc's two-condition publish protocol — is absent from the MVP entirely. Several roadmap gates worded as "PROOF" are satisfied by structural stubs (a compactor-outage proof that passes a `None` parameter to a pure function; a write-exclusivity proof against a capability stub that rejects everything).

**The counterweight — this is a genuinely well-engineered program at the code level.** Every landed slice has a child plan with provenance gates, allowed-file lists, and runnable verification commands. All new state-store/snapshot/transaction-handle tests execute in default CI. The tests are adversarial — fault-injecting backends, crash-point resume, field-by-field corruption, CAS-loss visibility, no-listing assertions — not smoke tests. The ~19k lines of new non-test code contain zero `unwrap()`/`expect()` and zero TODOs. And the issue mapping shows that roughly **80% of the 45 open July issues (#324–#368) map directly onto gates the six design docs predicted** — the failures are gates claimed without evidence or executed partially, not wrong architecture. The design is right; gate execution and landing discipline are what must catch up.

## 4. Program Rules and Invariants Assessment

The roadmap's ten Program Rules, audited as current-state invariants on origin/main:

1. **One production write authority per migrated scope — [DONE], but vacuously.** Exclusivity is enforced and tested per domain (`projection_outbox_acks.rs:650,667`; `external_location_metadata.rs:1223`; `path_governance_metadata.rs:978`; `workspace_binding_metadata.rs:722`; CurrentStateStore rejects all writes). 2. **Current path documented as migration adapter, not permanent peer — [PARTIAL].** Code-level framing exists (`state_store.rs:1-5,1647`; committed child plans state current authority remains ledger append → synchronous compaction). But no reference doc or ADR on origin carries the "migration adapter… not a permanent peer" framing — the framing survives only as a code comment plus unpushed local docs.
3. **Future Tier-1 writes end at StateToken; Parquet derived and watermarked — [DONE] for the not-yet-production path.** Control-store commits return StateTokens; token-pinned reads work; the adapter refuses synthetic tokens; freshness is exposed separately. Production Tier-1 writes still end at manifest-pointer CAS with no StateToken — the sanctioned pre-cutover state. #334 blocks this path becoming production.
4. **System tables/search/audit/lineage never enforcement or mutation surfaces — [DONE].** No authz or vending path reads `system.*` projections (grep of `authz/`, `credential_vending.rs`, `arco-uc/src` clean); authz compiles from metastore GrantRecords (`authz/grants.rs:27`). Adjacent risk, not a breach: #354's raw `commits.parquet` signed URLs defeat the projection-level redaction on the read side.
5. **Authz + vending fail closed on stale/missing state — [VIOLATED at the deployed boundary].** Engine level holds (authz denies on stale/unavailable compiled permissions, `authz/decision.rs:88-95`; vending denies on watermark mismatch and every missing-state branch, `credential_vending.rs:169-226`; UC routes 503 when the projection is absent — #362 confirms fail-closed, never mis-vend).
